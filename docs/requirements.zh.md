## 1. 项目背景与目标

本系统用于一个休闲羽毛球群的每周报名和收费，核心目标是让 Owner 在网页上直接看到每次活动的钱是否收齐，不再手动逐笔核对 Venmo。

**现状流程**

1. 微信群约 50 人，每周打一次球（目前固定周二），每次实际来 20–30 人。
2. 大家在截止时间前（例如周一晚上）在微信群接龙报名。
3. Owner 根据报名人数自行决定预订几块场地。
4. 打完球后，Owner 根据场地费和羽毛球消耗算出每人费用。
5. 每人通过 Venmo（少数用 Zelle）转账给 Owner。

**痛点**

- 付款零散，Owner 需要逐笔在 Venmo 里核对谁付了、谁没付。
- 报名、到场、费用计算全靠手工，容易出错。

**目标**

- 网页报名，截止后自动锁定并通知 Owner。
- 输入费用后自动按规则计算每人金额，并提供预填金额的 Venmo 付款链接。
- 自动读取 Venmo 收款通知邮件，标记已付款，Owner 能一眼看到是否收齐。
- 保留历史记录并提供有趣的出勤统计。

**使用者特点**：非公司、非商业，是普通的休闲娱乐群；不能使用商家收款平台，只能用 Venmo / Zelle 个人账户收款。

## 2. 技术方案与约束

整个系统运行在 Owner 自己的 Cloudflare 账号里（免费额度），网址为 https://jaysbadminton.llmat.dev；Venmo 收款邮件由 Gmail 自动转发给系统，数据每天自动同步一份到 Google 表格。具体实现见[技术设计文档（Technical Design）](technical-design.md)，Google 登录见 [Google 登录配置](google-login.zh.md)。

**组成部分**

| 组件 | 用途 |
| --- | --- |
| Cloudflare Workers | 提供网页（公开首页、申请页、活动页、成员专属页、Owner 管理页）和接口 |
| Cloudflare D1 数据库 | 存储成员、活动、报名、结算、付款、设置等全部数据 |
| Cloudflare 定时任务 | 每 15 分钟发送结算提醒和催款，并兜底检查报名截止 |
| Durable Object 闹钟 | 每个活动在截止前提醒和截止那一刻准时触发 |
| Cloudflare 邮件接收（Email Routing） | 接收 Gmail 转发来的 Venmo 收款通知邮件，收到即自动对账 |
| Gmail（Owner 和每位组织者自己的邮箱） | 用过滤器只转发 venmo@venmo.com 发来的邮件，系统不访问任何人的邮箱 |
| Telegram 机器人 | 向 Owner 发送通知（有组织者时，组织者负责的活动的通知发给组织者） |
| Google 表格 + Apps Script | 每天自动把数据同步到表格并保留快照，只用于查看和备份，在表格里修改不会写回系统 |

**已确认的约束与原因**

- **不能自动查询 Venmo 收款记录**：Venmo 不向个人开放查询接口；用脚本登录 Venmo 违反其用户协议，有账户被风控冻结的风险。因此改为由 Gmail 自动转发 Venmo 收款通知邮件给系统解析。
- **不能自动发起 Venmo 收款请求**：原因同上，且需要收集每个人的 Venmo 用户名，填错会把请求发给陌生人。改为由付款人点击预填金额的 Venmo 付款链接。
- **不使用 Venmo 对账单 CSV 方案**：需要 Owner 每次手动下载上传，不够方便。
- **微信群无法接入机器人**：微信不向个人群开放机器人接口，模拟登录个人微信违反条款、易封号。所以所有自动通知发到 Owner 的 Telegram，消息中附带可直接复制粘贴到微信群的文字。
- **Zelle 无法自动对账**：Zelle 通知邮件由各银行发送，格式不统一，通常无备注。Zelle 付款由 Owner 手动标记。
- 所有时间按**太平洋时间**处理。
- 系统规模：成员约 50 人，单次活动 20–30 人，Cloudflare 免费额度足够。

## 3. 角色与身份识别

系统通过两种方式识别成员身份：**Google 账号登录**（成员自助申请、自己登录），或「专属链接 + 二维码」（用邮箱注册的成员审核通过后由系统发到邮箱；Owner 也可以复制后通过微信私聊发放）。入口统一是首页的「登录 / 注册」。两种方式可以同时使用；一个 Google 账号只能对应一个人。一个邮箱也只能属于一个人：用 Google 申请或关联原来的专属链接时，如果这个 Google 账号的邮箱已经登记在另一位成员名下（邮箱或 Google 邮箱），系统拒绝并提示联系群主；关联的正是登记这个邮箱的成员时照常通过。Owner 在设置里绑定 Google 账号时也一样。

**角色**

- **Owner**：目前只有一个，界面上叫「群主」（原来叫「管理员」），拥有全部权限。负责审核成员、创建活动、修改名单、结算、确认付款。Owner 自己也是成员，可以报名打球。
- **组织者**（功能开关 `ORGANIZERS` 打开时才有）：Owner 从成员里任命，可以有多个。可以发起活动，管理自己负责的活动（名单、截止、结算、催款），钱收到自己的 Venmo / Zelle；成员和待审核只能看不能改，看不到别人负责的活动和收款。只用 Google 登录管理页。详见下面「成员管理」和第 8 节。
- **管理员**（同样在 `ORGANIZERS` 打开时才有，详见[设计文档](design/admin-role.zh.md)）：只有 Owner 能任命、降为组织者或撤销，可以有多个。像 Owner 一样管理整个群：审核申请、管理成员、任命和撤销组织者、管理和转交所有活动、确认所有收款、修改群设置、导出数据；自己发起的活动钱进自己的账户（和组织者一样）。只有 Owner 能做的：任命和撤销管理员、群主密码和管理链接、备份密钥、清空数据、Owner 的 Google 绑定和收款设置、Google 表格同步的开关和脚本、付款诊断、永久删除活动和收款、删除成员；管理员也不能对 Owner 和任何管理员（包括自己）的成员记录做链接、重新生成、停用等操作（改备注名除外）。只用 Google 登录管理页。
- **成员**：经 Owner 审核通过的群友，用 Google 登录或凭专属链接报名和查看自己的费用。
- **访客**：任何拿到公开链接的人，只能提交入群申请或查看公开的活动信息（只有人数，不显示名单）。

**入群申请与审核流程**

1. 申请人在首页点「登录 / 注册」→「用邮箱注册」，填写**用户名**（必填，全局唯一，重名时提示更换，显示在报名名单上）、**微信名**（必填，群昵称或微信号都可以，只要 Owner 能认出来；不规定格式）和**给群主的留言**（选填，最多 200 字，比如谁介绍来的），以及**邮箱**（必填，要输入两次，两次一致才能提交；一个邮箱只能属于一个人）。提交后 Owner 会收到 Telegram 提醒。提交时系统分配一个终身不变的成员编号（例如 M007）。
2. Owner 在管理页面看到待审核列表（显示申请人的邮箱）。
3. Owner 点「通过」：系统为该成员生成专属链接（包含一串随机、不可猜测的令牌）和对应的二维码图片，并自动把链接发到申请人的邮箱，Owner 不用再手动发送。页面上同样显示链接和二维码；邮件发送失败或邮件服务未配置时，Owner 可以在成员列表重试，或复制链接通过微信私聊发给对方。
4. Owner 点「拒绝」：直接删除该申请。

也可以用 Google 申请：在首页点「登录 / 注册」→「用 Google 登录 / 注册」，用 Google 账号登录，第一次填写和上面相同的表单（用户名、微信名、选填留言）即提交申请，同样进入「待审核」。Owner 通过后不用发链接，对方用这个 Google 账号登录即可报名（需要的话仍可在成员列表生成备用链接）。待审核的申请最多 30 条，满了以后新的申请会被拒绝，直到 Owner 处理掉一些。

**找回专属链接**：链接丢了的成员在「登录 / 注册」页点「找回我的专属链接」，填写邮箱（注册时留的，或在个人信息里填的）。如果这是已审核成员的邮箱，系统把专属链接再发一次；只用 Google 登录的成员收到登录方法。无论邮箱是否存在，页面的提示都一样（不泄露谁是成员）；同一成员每小时最多发一次。邮件提醒对方查看垃圾邮件文件夹（QQ、163 邮箱常把它放进去）。以前没有邮箱的老成员不受影响，可以在个人信息里补填邮箱。

**专属链接**

- 每个成员一个，长期有效。报名、修改报名、修改用户名、查看自己的费用和付款链接、查看个人统计，都通过这个链接。
- 只能操作自己的数据，不能修改他人报名。
- 链接丢失时，Owner 可以重新查看并再次发送；也可以「重新生成」，旧链接立即失效。
- 已知风险（可接受）：成员把链接转给别人，别人就能冒充他。

**成员管理**

- 成员可通过专属链接修改用户名（同样要求唯一）。系统内部用成员编号识别，改名后历史记录显示新名字。
- 成员退群时，Owner 可以「停用」该成员：不能再报名，停用时自动取消其在「报名中」活动的报名；专属链接仍然有效但只显示账单，有欠款可以继续付款；已截止活动中的报名和应付款保留。
- Owner 可以「恢复」已停用的成员（恢复为正常成员；以前停用时失效的链接会重新生成）。
- Owner 可以「删除」已停用且没有欠款、也不在任何还没收齐的活动名单上的成员（还在名单上的话，先等这场收齐归档，或者把他从名单上删掉；否则之后改费用会给一个已经没有链接的人出账单）：专属链接永久失效、Google 账号解除绑定，成员移到「已删除」；以前的报名、付款记录保留在历史名单和导出中。删除后用户名会释放给新人使用，旧记录的名字自动加上成员编号，例如「Alice（M004）」，所以历史名单和导出里不会和新的 Alice 混淆，几个同名的已删除成员也能区分。公开排行榜只统计正常状态的成员，停用和已删除的成员不上榜（见第 9 节）。
- 成员页的「已停用」「已删除」两个列表可以折叠。
- **组织者**（功能开关 `ORGANIZERS` 打开时，详见[设计文档](design/organizers.zh.md)第 8 节）：Owner 在成员列表点「设为组织者」任命（条件：状态正常、已关联 Google 账号；系统发邮件告诉对方，邮件服务没配置时页面提示 Owner 自己告诉他），点「撤销组织者」撤销；组织者也可以自己「不再当组织者」。成员页名字旁边有「组织者」标记，列表最上面的「组织者」区块列出每位组织者的任命时间、收款设置是否填好、转发是否生效、Telegram 是否连接、负责的未归档活动数，以及已撤销但还有活动在收款的人（「已撤销，还有 N 场在收款」）。撤销前弹窗列出受影响的活动：还没 Finalize 的活动负责人和收款人都转给 Owner；已 Finalize、还在收款的活动由 Owner 接手管理，钱继续付到原组织者的账户直到收齐；已收齐和已取消的不变。撤销后他的 Google 会话马上进不了管理页，系统发邮件告诉他哪几场的钱还会付到他的账户、什么时候可以删掉 Venmo 邮件转发。停用组织者时先自动撤销（恢复后是普通成员，要当组织者需要重新任命；以前停用时没撤销的，恢复时撤销，删除前要先恢复）；还是某场未归档活动负责人或收款人的人不能删除。Owner 和管理员还可以在活动页把活动「转交」给另一位组织者、管理员或 Owner：Finalize 前负责人和收款人一起换，之后只换负责人，已收齐或已取消的不能转。
- **管理员**（开关打开时）：Owner 在成员列表点「设为管理员」（组织者那一行是「升为管理员」，活动、收款设置和 Telegram 都保留），条件同组织者，系统发邮件说明管理员能做什么、不能做什么。管理员一行有「降为组织者」（保留活动）和「撤销管理员」（同撤销组织者：没 Finalize 的活动交回 Owner，已 Finalize 的由 Owner 接手、钱继续付给他直到收齐）；管理员也可以自己「不再当管理员」。成员页名字旁有「管理员」标记，最上面的区块改叫「管理员和组织者」。停用管理员只有 Owner 能做，会先撤销。
- **管理员的管理页**：标签页和 Owner 一样。「待审核」「成员」能操作（Owner 和管理员那一行没有按钮，已停用成员没有「删除」）；能任命、撤销组织者；「活动」列出所有活动，可以按负责人筛选、转交；「收款」看全部，已删除的收款只能恢复。「设置」有「给管理员的说明」、我的收款设置、Venmo 邮件转发、我的 Telegram（入群申请也发到这里）、默认外观、报名设置、提醒设置、导出数据、Google 表格同步状态（只读）、不再当管理员和退出登录；没有群主密码、管理链接、备份密钥、Owner 的 Google 绑定和收款设置、清空数据。
- **群操作记录**：成员页最下面可以展开「群操作记录」（Owner 和管理员可见），按时间倒序、每次 30 条：谁、什么时候、做了什么，用人名。记录通过 / 拒绝申请、改备注名、重新生成链接、停用（写明同时撤销的身份）、恢复、删除成员、任命 / 升降 / 撤销 / 自己不再当组织者或管理员、修改群设置和 Owner 的收款设置、开关表格同步、删掉最近的场馆、导出、转交活动。Owner 自己的操作也记；重复点击和没有变化的不记。清空所有数据时一起清空。
- **组织者的管理页**（开关打开时）：组织者用 Google 登录后，头像菜单和「我的活动」上方有「管理页」，打开 `/admin/google`。标签页和 Owner 一样（活动、收款、待审核、成员、设置），但只是 Owner 管理页的一部分：「活动」只列他负责的活动，可以新建活动（他就是负责人和收款人）、改名单（「添加人员」同样从正常状态的成员里选）、截止、结算、催款；「收款」只含付到他自己账户的钱和他的活动的账单，已删除的收款只能恢复，永久删除和清空是 Owner 的；「待审核」「成员」和 Owner 看到的一样（含邮箱、备注名、组织者区块），但只读：没有通过 / 拒绝 / 链接 / 重新生成 / 停用 / 恢复 / 删除 / 任命 / 撤销，备注名也只能看不能改；「设置」只有「给组织者的说明」（见第 10 节）、「我的收款设置」、Venmo 邮件转发的步骤和转发状态、「我的 Telegram」（连接自己的 Telegram 接收他负责的活动的通知，见第 8 节）、「不再当组织者」和退出登录。最近的场馆的 ✕ 和永久删除活动只有 Owner 有。Owner 的活动列表每场显示「负责人」，可以按负责人筛选。所有组织者能看到的页面都不含成员的专属链接。登录成员看到的活动卡片上，组织者负责的活动显示「组织：某某」（Owner 负责的不显示，公开页面也不显示）；截止后「需要修改请联系某某」和「某某在你名下加了朋友」也写这位组织者。

**Owner 管理页面登录**

- Owner 用一个专属的管理链接（加群主密码）进入管理页面，链接泄露时可重新生成。也可以在设置里绑定一个 Google 账号，之后用它登录 Google 就能直接进入管理页；一个 Google 账号只能对应一个人（群主或某个成员），群主也只能绑定一个。Owner 本人也打球（在名单和账单上），但不需要成员链接：在管理页打开活动，用「我的报名」报名、带朋友（不受带朋友上限限制），截止后到结算前仍可修改。Owner 用 Google 登录后从「我的活动」或活动页报名，规则相同。这些报名特权属于**本场负责人**（Owner 发起的活动就是 Owner；组织者功能见[设计文档](design/organizers.zh.md)）：在别人负责的活动里，Owner 用成员页报名时和普通成员一样，要改名单直接用管理页。

## 4. 活动管理

每次活动由 Owner 手动创建，系统不自动按周生成。

**创建活动时填写**

| 字段 | 说明 |
| --- | --- |
| 日期 | 必填，每次手动选择，不预填 |
| 开始时间 / 结束时间 | 必填；默认填上一次活动的时间 |
| 场馆 + 地址 | 场馆名必填，地址选填。第一次输入时把场馆和地址一起存下来；之后从「最近的场馆」里点一下，名字和地址自动填好；不再用的场馆点 ✕ 从列表里删掉（已经建好的活动不受影响）。地址输入时自动联想美国地址（也可以直接输入球馆名搜索），活动页上的地址可以点开地图 |
| 报名截止 | 必填；选择在活动开始前提前几天几小时截止（例如提前 1 天 0 小时），系统自动算出截止时间，保证早于活动开始；默认上次的选择（时间、场馆、截止提前量按发起人各记各的：组织者记自己的，还没发起过时用 Owner 的；最近的场馆列表大家共用） |

创建后生成一个公开的活动页面链接，Owner 发到微信群；成员通过自己的专属链接或 Google 登录报名。

**活动状态**

1. **报名中**：成员可报名、修改、取消。
2. **已截止**：成员端锁定，只能查看；Owner 仍可修改名单。Finalize 前 Owner 可「重新开放报名」，新的截止时间最晚可到活动结束时间。
3. **已 Finalize**：Owner 输入费用并点 Finalize，金额生效，成员看到付款链接。
4. **已收齐**：所有应付款人员都已标记为已付。活动立即归档：不再发送该活动的通知，Owner 也不能再修改名单、到场、费用或付款标记；如有错误由 Owner 私下手动解决。

另有一个**已取消**状态：活动取消不产生任何费用，也不计入出勤统计。

**其他规则**

- 允许多个活动同时存在，例如上一次还没收齐钱时就创建下一周的活动，各活动相互独立。
- 球的单价记住上次的值，新建结算时自动预填（按活动的负责人分别记）。
- 创建活动时，如果算出的截止时间已经过去，提示调整，不允许创建。
- Finalize 前 Owner 可以取消活动；Finalize 之后不能取消。
- Owner 可以对报名中的活动「立即截止报名」（例如人数已够），之后仍可重新开放。
- 紧急情况下（场地变更、时间临时调整），Owner 可以修改活动的日期、时间和地点，无论是否已截止或已开始；已收齐归档或已取消的活动不能修改。活动编号和活动代号都不变，已发出的链接和付款编号继续有效。报名中的活动的截止时间跟着开始时间一起移动，和开始时间的间隔不变（包括重新开放报名时设的截止时间），但不会晚于活动结束；若已过则立即截止。只改标题或地点时截止时间不变。修改不会自动通知任何人，需 Owner 自己在群里说明。
- 重新开放报名后，截止前提醒和截止通知按新的截止时间重新发送。
- **预定场地**：活动管理页有「预定场地」卡片，负责人（Owner、管理员或这场的组织者）在 Finalize 之前随时可以填写或修改今天订到的场地编号，可以填多个。编号 1–99，用下拉菜单点选（可以连点几个），也可以直接输入后点「添加」或按回车；点编号上的 ✕ 去掉，最后点「保存场地」。名单上的成员在活动卡片上看到「场地：3、5、12 号」（首页的下一场活动也显示），活动开始前 10 分钟的推送里也写上；没报名的人和公开页面不显示。
- **操作记录**：活动管理页底部可以展开「操作记录」，按时间倒序列出这场活动的每次改动：谁（这个人的名字，群主也写名字；或「系统」）、什么时候、做了什么。记录的操作有：创建、修改活动、提前截止、重新开放、取消、转交（包括撤销组织者时活动交回群主）、名单的添加 / 改名 / 删除、负责人自己报名和取消、到场标记、Finalize 和之后修改费用（写明原来的费用）、标记已付、撤销付款、已退款、把待确认的 Venmo 收款关联到账单（钱付到了别人的账户时写明「钱在 某某 的账户」）、忽略待确认的收款和把它移回待确认（记在备注编号对应的活动上；备注里没有活动编号的不记）、停止 / 恢复账单提醒、修改预定场地（写明原来和现在的场地）、停用成员时把他从报名中的活动移出。修改活动时写明每项的原值和新值，包括跟着移动的报名截止时间。Venmo 自动对账和全部付清后自动归档记为「系统」。没有实际改动的操作不记。成员自己报名、修改、取消不记。Owner 能看所有活动的记录，组织者只能看自己负责的活动，成员看不到。永久删除活动时记录一并删除。
- 每个活动在创建时生成一个活动编号，取活动日期（如 jbm20261006），用于付款编号；同一天有第二场活动时加字母后缀（如 jbm20261006b）。活动编号一旦生成就永远不变（修改日期也不变），也不会再分配给别的活动（包括已删除的活动），是唯一的。活动链接里的活动代号取编号的月日和字母（如 1006、1006B）。

## 5. 报名

报名只能由成员本人进行（专属链接或 Google 登录），或由 Owner 在管理页添加；Owner 最终确认的名单即为「报名名单」，是分摊场地费的依据。

**成员报名**

- 在专属页面看到当前开放的活动，点「报名」即可。
- 截止前可以随时修改（例如改带朋友人数）或取消报名。取消报名时，挂在他名下的朋友（包括 Owner 加的）一起取消，确认框会写明朋友人数。
- Owner 可以只在某个成员名下挂朋友、成员本人不来。这时成员的页面写明「你本人没有报名，群主在你名下加了 N 个朋友，费用算在你的账单上」，截止前可以点「我也报名」把自己加上（名下的朋友保留），或者点「去掉这些朋友」。
- 截止后成员端锁定，只能查看。
- 不设人数上限，不设候补名单。

**带朋友**

- 报名时可选择带 0 到 N 个朋友。N 由 Owner 在全局设置中调整，**默认 3**。
- 名单上已经超过 N 个朋友时（例如 Owner 代加的，或者 N 后来调小了），成员修改报名可以保留现有的朋友，但不能再加。
- 每个朋友可填写名字（选填）；不填则显示为「某某的朋友1」「某某的朋友2」。
- 朋友视为正常报名人员：计入报名人数，参与场地费分摊；如到场，参与球费分摊。
- 朋友的全部费用由带他来的成员负责，合并到该成员的应付金额中。
- 朋友不需要专属链接，也不进入成员名单和个人统计。
- 两个成员之间互相代付的功能不做；需要时用带朋友功能代替。

**Owner 覆盖修改**

- 截止后、归档前（包括 Finalize 前后）Owner 可在管理页面添加、修改、删除名单中的人员，包括添加成员、添加朋友、删除成员。
- 当天没报名临时来的人，只能由 Owner 加入名单，视为报名人员（同样分摊场地费）。临时来的非成员必须作为「朋友」挂在本场收款人（Owner 的活动就是 Owner 自己）或某个成员名下，挂在谁名下由 Owner 决定，费用由该人承担；挂在收款人名下时自动算已付。临时挂的朋友不受带朋友上限 N 限制。
- 有人报了名找人顶替，Owner 删掉原报名者并加入顶替者。

**公开活动页面**

- 任何人可看（公开首页和活动页）：活动标题（如有）、日期（含年份）、时间、场馆和地址、截止时间、报名人数（含朋友）。**不显示报名名单和任何收款状态**：进行中的活动只显示「报名中」或「已截止」，已取消的显示「已取消」，过往活动不显示状态。
- 新建活动时可以填一个选填的标题（最多 30 字，如「HappyTuesday 比赛」），显示在日期上方，也出现在 Telegram 消息和导出里；不填就只显示日期。
- 不显示任何费用和付款状态。
- 不能在公开页面报名或修改。

**成员看到的名单**：自己报了名的成员，在专属页面的这次活动卡片上可以看到完整名单（所有报名的人和他们带的朋友，朋友排在带他的人后面，标注「某某带」，自己标「我」）。活动结算后，没来的人显示为灰色，并标出「X 人未到」。没报名的成员和公开页面仍然只看到人数。即将开始的活动名单默认展开，已结算的默认折叠。

**报名人数提示**：系统只显示报名总人数（含朋友），**不计算也不建议场地数量**，订几块场由 Owner 决定。

## 6. 结算与费用规则

场地费由所有报名人员平摊，球费由所有实际到场人员平摊；朋友的费用计入带他来的成员。

**Owner 输入**

1. 场地总费用（美元，最多 $5000）
2. 羽毛球消耗个数（最多 500 个）
3. 羽毛球单价（美元，默认上次的值，最多 $20）

上限只为挡住手误（多打一个 0 之类），超过时提示检查。
4. 到场标记：默认名单上所有人（含朋友）都「已到场」，Owner 在 Finalize 前把没来的人改为「未出席」；朋友可以单独设置。

**计算公式**

```latex
\text{每人场地费} = \frac{\text{场地总费用}}{\text{报名人数}}
```

```latex
\text{每人球费} = \frac{\text{消耗个数} \times \text{单价}}{\text{到场人数}}
```

- 报名人数、到场人数均包含朋友。
- 报名并到场：场地费 + 球费；报名未到场：只付场地费。
- 成员应付金额 = 本人份额 + 所带全部朋友的份额。
- 按「分」**精确分摊**，每人加起来正好等于总费用：每一份先付相同的基本金额（向下取到分），除不尽剩下的几分钱**随机**挑几份各加 1 分（不固定给排在前面的人）。随机按报名记录算出，同一场活动每次计算、每次打开结果都一样。成员应付 = 本人和每个朋友的每一份相加。例如总费用 40 美元分 3 份：随机一份 13.34，另外两份 13.33。
- 2026-10-19 以前保存的结算沿用旧规则（每份向上取整到分，总额可能多几分钱），金额不会自己变；在结算卡片上重新「保存修改」后改用精确分摊。
- **本场收款人**（钱进谁的账户：Owner 发起的活动是 Owner，组织者发起的是组织者本人）及其所带朋友的份额自动标记为已付。Owner 去打组织者的球，和其他人一样要付钱给组织者。

**示例**：报名 24 人、到场 22 人，场地费 240 美元，用球 20 个、每个 3 美元。每人场地费 10.00；球费 60 美元 = 6000 分，÷ 22 = 272 余 16，所以随机 16 位到场者球费 2.73、其余 6 位 2.72。到场者付 12.73 或 12.72，未到场者付 10.00，合计正好 300 美元。

**Finalize**

- 结算页面有「Finalize」按钮。点击前 Owner 可以反复修改输入、预览每人金额。
- 点击 Finalize 后金额生效，成员专属页面才出现应付金额和 Venmo 付款链接（Finalize 前不显示，避免提前付款）。
- 名单是空的不能 Finalize。所有人都标成「未出席」但填了球费时，结算卡片上和 Finalize 确认框里都会提醒：球费没有人分摊，不会算进任何人的账单。

**Finalize 之后的修改**

- 归档（已收齐）之前，Owner 仍可修改名单、到场情况和费用；归档后不可修改。
- 所有人的金额都按新数据重新计算（包括已付款的人和 Owner 自己），保证费用由所有人公平分摊。
- **已付款**的人：新金额更高时变成「部分付款」，显示还差多少，可以补付；新金额更低时仍是已付，显示多付金额，Owner 退款后点「已退款」。
- **收款人**自己的账单始终是已付，自动标记的收款金额跟着新金额变（这笔不能撤销）。
- 已付款的人被移出名单：他带的朋友留在名单上，朋友的费用仍算在他的账单上；没有带朋友的话应付变为 0，付过的钱全部列为需要退款，总费用由其他人分摊。付过又已全额退回的人被移出名单，账单同样保留（应付 0），付款和退款记录都留着；从没付过的人账单直接删除。收款人被移出名单时账单直接删除；但如果有 Venmo 付款关联在收款人的账单上，账单保留（应付 0），那笔钱列为需要退款。
- Finalize 之后，会让费用没人分摊的修改直接拒绝并说明原因：用球费用不为 0 时把最后一个到场的人标成未出席（或移出名单），或者有费用时把名单删空。确实如此的话，先把用球个数或费用改成 0 再保存。
- 每一笔付款和每一笔退款都单独记录。Owner 点「已退款」时记一笔退款，金额是当时多付的部分。净付款（付款合计 − 退款合计）达到最新应付金额才算付清，所以退款后金额又变高时，会显示还差多少。
- 「收齐」的判断标准是**所有应付款人员都已标记为已付**，而不是比较金额总数。

## 7. 付款与对账

付款以 Venmo 为主，系统接收 Owner Gmail 转发来的 Venmo 收款通知邮件、按备注编号自动标记已付款；匹配不上的和 Zelle 付款由 Owner 手动标记。

**成员端付款**

- Finalize 后，成员专属页面显示：本次应付金额（含明细：本人场地费、球费、各朋友份额）、付款状态、Venmo 付款按钮。
- Venmo 付款按钮为预填链接，包含本场收款人（Owner，或发起这场的组织者，账单上写「付给 某某」，群主也写群里的名字，不写「群主」）的 Venmo 用户名、金额、备注。备注带唯一付款编号，例如「xiaoming-jbm20261006-m007」（全小写：用户名 + 活动编号（创建活动时按日期生成，如 jbm20261006，同一天第二场加字母，如 jbm20261006b；之后改日期也不变）+ 成员编号；中文用户名转拼音，英文转小写、空格变下划线；付款编号在 Finalize 时生成，之后不随改名变化。短、唯一、易于从邮件中提取）。
- 页面同时以文字显示收款人的 Venmo 用户名、金额和备注编号，供链接打不开时手动转账。
- 页面提示：在微信内置浏览器中如果打不开 Venmo，请点右上角选择「在浏览器中打开」。
- 页面显示收款人的 Zelle 账号作为备选，并提示 Zelle 付款需由收款人手动确认。

**自动对账（Venmo）**

- Owner 在 Gmail 里设过滤器，把 Venmo 官方发来的收款通知邮件自动转发到 venmo@jaysbadminton.llmat.dev，系统收到后立即处理：发件人为 venmo@venmo.com，标题形如「Yue Sun paid $7.00 to your Venmo account. Leave it in Venmo or transfer it to your bank account.」。只转发和处理这类邮件，系统接触不到其他邮件；伪造的「Venmo 邮件」会被拒绝；只处理系统启用之后收到的邮件。
- 从邮件中提取付款人、金额、备注，按备注中的付款编号匹配到对应活动和成员，标记为已付款，并记录付款时间和金额。
- 按 Venmo 交易编号去重，同一笔交易只处理一次，避免重复处理。
- Owner 会把所有 Venmo 收款邮件都转发过来，其中大部分与羽毛球无关，按以下规则处理：
  1. 编号能找到对应活动里对应的人（名字和成员编号是同一个人）→ 这笔钱记到这个人的账上。一笔应付款可以分多次付，每一笔都单独记录（时间、金额、付款人）：
     - 累计金额等于应付 → 已付款。
     - 累计金额不足 → 「部分付款」，显示还差多少；成员页的 Venmo 按钮改为只付剩余金额，之后同一编号的付款继续累加，直到付清。
     - 累计金额超过应付（多付，或者付了两次）→ 算已付款，同时列入「需要退款」：显示应付多少、每一笔付了多少、需要退多少；Owner 退款后点「已退款」。活动已收齐归档后又收到的付款也照此处理。
  2. 编号的 jbm 部分能找到对应活动（或已永久删除的活动），但后面的 m 编号对不上这次活动有应付款的人（或名字和编号不是同一个人、活动还没结算、已取消、已从数据库永久删除）→ 列入「待确认」并通知 Owner。
  3. 没有备注、备注里没有本系统格式的编号、找不到对应活动、或者名字对不上群里任何人 → 当作与羽毛球无关的收款，直接忽略，不保存、不通知。
  4. 邮件解析失败 → 忽略。
- **有组织者时**（详见[设计文档](design/organizers.zh.md)第 6.2 节）：每位组织者在自己的 Gmail 里设同样的过滤器，转发到同一个地址。系统先看钱进了谁的账户：「Sent to」和收件邮箱同时对上 Owner 的收款设置、某位组织者（包括已撤销的）的收款设置、或 60 天内改掉的旧账户，就是这个人的账户；谁的都对不上 → 和以前一样当作「收款账号不一致」提醒 Owner。规则 1 还要求这场活动的收款人就是这个账户的主人；不是（比如 Owner 活动的钱付到了组织者的账户）→ 列入「待确认」，原因写「付到了 @xxx（某某）的账户，但这场的收款人是 某某」。已撤销的组织者，他收款的活动还没全部归档时照常对账；都归档、取消或删除以后（失效），他账户里带本群付款编号的钱列入「待确认」由 Owner 处理，其他邮件静默丢弃，不报「收款账号不一致」；失效那一刻系统发邮件提醒他删掉转发过滤器（撤销时就没有收款中的活动的，撤销邮件已经说过，不再发），每人只提醒一次。
- Owner 只需要看「待确认」列表，把每一笔关联到某次活动某个人的应付款，或者忽略。可选的应付款先列未付清的（还在收款中的活动），再列已付清的（还在收款中的活动，以及 60 天内归档的活动；那场收款人本人的不列）：同一个人付了两次（比如付过现金又用 Venmo 付了一次）时，关联到已付清的账单，多出的钱进入「需要退款」，和自动对账一样。归档 60 天内的活动上只能撤销这种多付的 Venmo 付款（撤销后账单仍是付清的），它会回到「待确认」。
- 收款页另列「已忽略」（全部，直到删除）和「最近关联的」（最近 30 笔）。忽略错了可以在「已忽略」里「移回待确认」，再关联到账单。
- 有组织者时，每笔收款记着钱进了谁的账户：组织者的收款页只有进了他自己账户的钱，关联时只能选他负责的活动的账单；Owner 看全部，进了组织者账户的那些标着「进了 某某 的账户」。钱在别人账户里的收款只有 Owner 能关联到这场的账单（组织者只能忽略后退给付款人），关联后账单的付款记录上标「钱在 某某 的账户」，两人自己结算。在账单里撤销一笔 Venmo 付款时，回到待确认的那笔仍记在原来的账户名下（自动对账记上的那笔记在这场收款人名下）。
- 待确认和已忽略的收款可以「删除」（不用确认），进入「已删除」：保留 30 天后由定时任务永久删除。「已删除」里每一笔可以「恢复」（回到原来的列表）或「永久删除」，都要弹窗确认；「清空」永久删除全部，需要群主密码和弹窗确认。已关联到账单的收款不能删除，要在账单里撤销。

**Venmo 收款通知邮件样本**（Owner 提供的真实邮件正文，与羽毛球无关）

```text
Yue sun paid you

$7.00
Milktea9/27

Money credited to your Venmo account.
Transaction details
Date
Sep 28, 2026

Transaction ID
77B44894RT023271X

Sent to
@KeLi8916
```

**解析规则**

| 字段 | 提取方式 | 样本中的值 |
| --- | --- | --- |
| 付款人 | 第一行「paid you」之前的文字（Venmo 显示名，不是系统用户名） | Yue sun |
| 金额 | 之后第一个「$」开头的金额 | 7.00 |
| 备注 | 金额之后、「Money credited to your Venmo account.」之前的文字 | Milktea9/27 |
| 付款日期 | 「Date」下一行 | Sep 28, 2026 |
| 交易编号 | 「Transaction ID」下一行；作为去重依据，同一编号只处理一次 | 77B44894RT023271X |
| 收款账号 | 「Sent to」下一行；必须等于设置中的 Owner Venmo 用户名（有组织者时，或者某位组织者的），否则忽略 | @KeLi8916 |
| 收件邮箱 | 邮件的收件人（To）；必须等于同一个人设置中的「Venmo 通知邮箱」（Venmo 账户登记的邮箱，填 Venmo 用户名时必填），否则忽略 | （Owner 的邮箱） |

- 付款编号在备注中按「名字 - 活动编号（jbm + 8 位日期 + 可选字母）- m + 成员编号」查找，不区分大小写，允许多余空格；名字必须是群里某个人的（当前用户名的拼音，或者账单上印的名字，改名后旧账单仍能对上）；备注里可以有其他文字。
- 上面的样本备注是「Milktea9/27」，不含付款编号，属于与羽毛球无关的收款。
- 邮件是 HTML 格式，系统把 HTML 转成文字后解析；已用真实邮件测试。解析失败的邮件忽略。
- 付款人名字在标题和正文中大小写可能不同（Yue Sun / Yue sun），以正文为准，只用于显示，不参与匹配。

**手动操作（Owner）**

- 可手动将任何人标记为「已付清」（用于 Zelle、现金等），系统按还差的金额记一笔手动付款。
- 归档前可撤销任意一笔付款记录（手动的或 Venmo 的）；归档后 60 天内只能撤销多付的 Venmo 付款。手动的直接删除；Venmo 的一律回到「待确认」，钱不会从系统里消失：从「待确认」关联过来的那笔重新打开，自动对账记上的那笔新建一条「待确认」，原因都是「从账单撤销的 Venmo 付款」，Owner 可以再关联到正确的账单。可对某个活动点「停止账单提醒」：不再发送每日汇总和催款消息，但活动不归档，未付记录保留。

**隐私规则**

- 成员只能在自己的专属页面看到自己的金额和付款状态。
- 所有人的付款情况只有 Owner 和管理员能看到；组织者只能看到自己负责的活动的付款情况，以及付到自己账户的收款（包括付错到他账户、属于别的活动的）。
- 公开活动页面不显示任何费用信息。

**跨活动欠款**：每次活动独立结算、独立付款，金额不合并；成员专属页按活动分别列出每个未归档活动的应付金额和付款链接。

## 8. 通知（Telegram）

没有组织者和管理员时，所有自动通知只发给 Owner 的 Telegram；每条消息分两部分：上面是给 Owner 看的详细信息，下面是一段排好版、可直接复制粘贴到微信群的文字。

**有组织者时**（功能开关 `ORGANIZERS` 打开，详见[设计文档](design/organizers.zh.md)第 7 节）：每位组织者在自己的「设置 › 我的 Telegram」连接自己的 Telegram（绑定码按人保存，两人同时连接互不影响；断开、发送测试消息也按人）。下表里和某场活动有关的通知（截止前提醒、报名截止、结算提醒、结算完成、每日收款汇总和催款文字、收齐、部分付款、多付）发给**这场的负责人**；负责人没连 Telegram、已经不是组织者、功能开关关着或者发送失败时改发给 Owner，消息开头写明原因（例如「组织者 某某 还没连接 Telegram，这条发给群主」）。负责人是组织者或管理员时 Owner 另外收到三条抄送：新活动发起（Owner 自己建活动不发）、结算完成、收齐。「待确认」按钱进了谁的账户发：现任组织者的账户发给他（没连 Telegram 等情况同样改发 Owner 并写明原因），Owner 和已撤销组织者的账户发 Owner。「转发可能中断」按账户分别检查：现任组织者的账户发给他并抄送 Owner，Owner 和已撤销组织者的账户发 Owner。Gmail 转发确认邮件里提到的邮箱是某位现任组织者的 Venmo 通知邮箱时，确认内容显示在他的「设置 › Venmo 邮件转发」里（24 小时后清掉），连了 Telegram 也发一份；对不上任何组织者的仍发 Owner。入群申请发给 Owner 和所有连了 Telegram 的管理员（有一人收到就算发出；开关关时只发 Owner）。管理员负责的活动和组织者一样发给他本人，Owner 的三条抄送写「管理员 某某」。转交活动在 Finalize 前换了收款人、操作人又不是原收款人时，原收款人（Owner 或现任组织者、管理员）收到一条通知。Venmo 邮件异常、每周健康简报、备份密钥、收款设置被修改等其余通知仍只发 Owner；组织者改了自己的收款设置，Owner 和他本人都会收到。发给组织者的消息提到「管理页」时附上他的入口 `/admin/google`（用 Google 登录），不是 Owner 的管理链接；组织者给机器人发「管理页面」，回复的也是这个入口，Owner 的管理链接只发给 Owner。微信群文字里加上「（组织：某某）」，负责人是 Owner 时不加。撤销组织者时断开他的 Telegram。

**配置**：网站维护者通过 BotFather 创建一个机器人，令牌放在 GitHub secret `TELEGRAM_BOT_TOKEN`，部署时同步到服务器。Owner 在设置页点「连接 Telegram」，系统生成一个 10 分钟内有效、只能用一次的链接，打开后在机器人对话里点 Start 即完成绑定。每个人（Owner、每位管理员和组织者）各记一个接收人，其他人给机器人发消息一律忽略；重新连接会替换这个人旧的账号，清空所有数据后需要重新连接。设置页面提供「发送测试消息」和「断开连接」。已连接的 Owner 给机器人发送「管理页面」（或 /admin），机器人回复当前管理链接（只回复已连接的账号；打开后仍需输入密码）。Gmail 添加转发地址时发来的确认邮件（经签名校验确认来自 Google）会转发到 Owner 的 Telegram，Owner 可以独立完成转发设置。

**语言**：机器人的消息有简体、繁體和 English 三种，每个已连接的聊天各自选择，和网页的语言设置无关。给机器人发「语言」（或「語言」、language、/language），机器人在输入框下方列出 简体中文 / 繁體中文 / English 三个按钮，点一个以后的通知就用这种语言。没选过的聊天用简体；新连接时 Telegram 设成繁体中文的默认繁體。可复制到微信群的文字始终是简体（发给全群看的）；管理页的名称（如「收款」「设置 › …」）英文消息里照原样写中文，因为管理页只有简体。

| --- | --- | --- | --- |

**成员推送通知**：成员可以在自己的页面开启浏览器推送（「我的活动」上方提示一次，「个人信息 › 推送通知」可以随时开关；每台设备分别开启，开启后马上收到一条「推送已开启」）。推送这几种消息：有人发起新活动时，推给所有正常状态的成员（发起人自己除外），内容是谁发起、时间、地点和报名截止时间；活动开始前 10 分钟，推给名单上的成员（包括只有朋友在名单上、挂在他名下的成员），内容是时间、场馆和预定场地（填了的话，例如「场地：3、5 号」），活动已取消、已 Finalize 或本人已不在名单上就不推；第一次 Finalize 时，推给这场还要付钱的成员，内容是他要付的金额和付给谁（例如「你需要付 $12.73，付给 Jay」），之后修改费用不再推送；别人（群主、管理员或组织者）在管理页面替成员改了报名时，推给这位成员：用「添加人员」把他或他带的朋友加进名单（「Jay 帮你报了名」）、把他或他带的朋友移出名单（「Jay 把你移出了名单」，Finalize 之后还会说账单已重新计算）、取消活动（推给名单上所有人：「Jay 取消了活动」），自己改自己的报名不推送。开启推送的设备很多时，每批发 20 条，一批发完 1 秒后发下一批。点通知打开成员自己的页面（用 Google 登录的打开活动页面）。iPhone / iPad 需要先在 Safari 里「添加到主屏幕」、从主屏幕打开后才能开启；微信里打开的网页不支持推送。更换成员专属链接或群主解绑 Google 账号后，服务器上这个人的推送全部清掉：拿着旧链接或旧账号的设备不再收到，本人的设备下次打开自己的页面时自动恢复；删除成员后全部停止；退出 Google 登录会停止这台设备的推送。同一台设备上换另一位成员开启，推送就改发给他。

「截止前提醒」和「报名截止」由每个活动的闹钟在那一刻（几秒内）发出；定时任务每 15 分钟运行一次，其他定时类通知（结算提醒、催款、每周汇总）最多延迟约 15 分钟；收款相关的通知（收齐、待确认）在收到邮件时即时发送。

## 9. 历史记录与统计

系统保留所有活动的完整记录；统计分为公开排行榜（只涉及出勤）和个人统计（含费用，仅本人可见）。

**历史记录**

- 公开首页：过往活动列表（日期、地点、报名人数）。排行榜是否在首页展示由 Owner 在设置「公共页面」里开关（默认展示）。
- Owner：每次活动的完整结算明细和付款记录。
- 已取消的活动保留记录，但不计入统计。

**公开排行榜**（只统计正常状态的成员，不含朋友；停用和已删除的成员不上榜）

- 今年出勤次数排行
- 最长连续出勤次数（按连续活动场次计算，已取消的活动跳过不计）
- 带朋友最多的人

**个人统计**（专属页面，仅本人可见）

- 今年来了几次、总共来了几次
- 今年总花费、平均每次花费
- 与去年同期的对比

个人统计中的花费按本人的账单计算（包含所带朋友的份额）。

出勤以 Owner 结算时的到场标记为准；报名未到场不算出勤。「今年」「去年同期」均按太平洋时间的自然年计算。具体统计项目可在实现时补充更多有趣的内容。

**个人信息**（专属页面的一栏；Owner 在成员列表点名字也能看到同样内容）

- 基本信息：名字、微信名、邮箱、入群时间（年月日 + 时间，太平洋时间；以审核通过时间为准）。
- 邮箱：成员可以在这里自己填写或修改；没填时显示 Google 登录的邮箱（如果有），清空即改回 Google 邮箱。
- 活动记录：GitHub 式热力图，每格一天、每列一周，覆盖过去一年，并延伸到已报名的最后一场。绿色 = 已参加，红色 = 报名但缺席（以结算时的到场标记为准），蓝色 = 已报名还没进行；取消的活动和朋友不计入。点一格显示当天的活动和场地，上方汇总过去一年参加、缺席、即将参加的次数。
- 备注名：只有 Owner 和管理员能填写（最多 40 字），Owner、管理员和组织者能看到（开关打开时，填写处写「只有群主、管理员和组织者能看到」），也显示在管理页成员列表的名字下方，方便识别；成员自己看不到，也不出现在任何公开页面。导出的成员表包含邮箱和备注名。

| 公开活动页 | 公开链接（每个活动一个） | 单个活动的信息、报名人数（不显示名单），附公开首页链接；已用 Google 登录的成员在这里看到自己的报名卡片（完整名单、报名 / 修改 / 取消、账单） |
| 登录 / 注册 | 首页「登录 / 注册」，或头像菜单 | 两个选项：用 Google 登录 / 注册（第一次登录时申请入群或关联原来的专属链接），或用邮箱注册；另有「找回我的专属链接」。登录后显示与成员专属页相同的「我的活动」 |
| 成员专属页（我的活动） | 成员专属链接 / 二维码 | 自己报名的活动（不论最后是否到场），从新到旧排列：报名（含带朋友）与修改、名单、本人应付金额与 Venmo 付款按钮、付款状态；下面是「可以报名」的活动；已经结束且付清的活动折叠在「历史活动」里，默认不展开，点进去仍能看到这场的名单、本人金额和是否付清 |
| 个人信息 | 我的活动页上方的「个人信息」，或头像菜单 | 顶部资料卡（名字、微信名、入群日期、过去一年打球/缺席/即将参加次数）、我的花费（图表）、活动记录（热力图）、资料与设置列表（名字、邮箱、添加到主屏幕、推送通知，点一行在下面展开修改）、绑定 Google（用专属链接时）；退出登录在头像菜单里 |

| 管理员和组织者的管理页 | 管理员或组织者用 Google 登录后，头像菜单或「我的活动」上方的「管理页」（`/admin/google`） | 管理员：除 Owner 专属的部分外和 Owner 一样，见第 3 节「管理员的管理页」；组织者：Owner 管理页的一部分，见第 3 节「组织者的管理页」。设置页有「给管理员的说明」或「给组织者的说明」 |

**Owner 管理页功能**

- 待审核申请：通过（显示链接和二维码，并自动发到申请人的邮箱）/ 拒绝。
- 成员管理：查看链接和二维码、重新生成链接、停用 / 恢复 / 删除成员；点名字查看成员的个人信息和活动热力图，并填写只有自己能看到的备注名。
- 活动：新建（可勾选「我自己也报名」，默认勾选）、取消、查看报名名单、添加/修改/删除人员。
- 结算：输入三个数字、标记到场、预览金额、Finalize、Finalize 后修改。
- 收款看板：应收总额、已收金额、每人状态（未付 / 部分付款还差多少 / 已付 / 多付需退款）和每一笔付款明细、手动标记已付或撤销某一笔、停止账单提醒。
- 收款页：「需要退款」列表（标记已退款）和「待确认」列表（带原因，可关联到某人的应付款或忽略）。
- 收款设置（单独一栏，平时只读显示；修改时需要输入群主密码，每次修改都会通知 Owner 的 Telegram）：Venmo 用户名、Venmo 通知邮箱、Zelle 账号。不能填组织者正在用或 60 天内用过的 Venmo 用户名、通知邮箱（一个 Venmo 账户只能属于一个人，否则系统分不清钱进了谁的账户）。
- 管理员和组织者有自己的「我的收款设置」（不需要群主密码，因为只能用 Google 登录）：同样三项，唯一性规则同上；没填好 Venmo 用户名和通知邮箱时不能 Finalize 自己的活动。还有没收齐的账单时改 Venmo，旧账户继续认 60 天，且不能清空。每次修改通知 Owner 的 Telegram。
- 设置：网站标题、默认外观（两种风格各 4 个强调色）、排行榜开关、带朋友上限 N（默认 3）、连接 Telegram、提醒设置：截止前提醒开关和提前小时数（默认 6 小时）、账单提醒时间（默认上午 10 点）、每周健康简报；Google 表格同步在二级页面。
- 备份网站密钥：输入群主密码后，把网站的加密密钥（TOKEN_KEY，用来加密保存成员链接、管理链接和 Google 表格同步的密钥；丢了的话，成员链接无法再显示或找回（只能重新生成），群主密码会被重置，Google 表格同步要重新生成密钥并粘贴新脚本）发到 Owner 的 Telegram，存进密码管理器和 GitHub secret 后删掉那条消息。每次部署都会核对这个备份，密钥丢失时部署会自动用它恢复。
- 使用指南（设置页，危险操作上方）：第一次设置后要做的事（自动显示哪些已完成）、Venmo 邮件转发的设置与测试（显示最近一次收到邮件的时间和处理结果）、忘记密码或管理链接怎么办；开关打开时还有「组织者」和「管理员」两节（怎么任命、他要做什么、钱和通知怎么走、转交和撤销；管理员能做和不能做的事、群操作记录）。
- 给管理员的说明（管理员的设置页最上面）：和给组织者的说明一样的三项准备，加上他能做和不能做的事。
- 给组织者的说明（组织者的设置页最上面）：开始前要做的事，做好的自动打勾：填收款设置、设 Venmo 邮件转发、连接自己的 Telegram（网站没配置 Telegram 机器人时不列这一项）；以及怎么组织一场活动。
- 从数据库永久删除活动：活动详情页底部，只对已收齐归档或已取消的活动显示（例如测试用的活动；还有未付账单的活动要先收齐或标记已付）。需要输入群主密码并在弹窗里再次确认；活动和它的报名、账单、付款记录、匹配到的 Venmo 收款、通知记录在一个事务里一起删除，截止提醒闹钟一并清除。只保留它的日期和编号，这个编号以后不会再分配给新活动，迟到的付款会进入「待确认」而不会记到新活动的账单上。之后排行榜、成员花费立即不再计入，Google Sheets 在下一次每日同步时覆盖掉这些行。操作会通知 Owner 的 Telegram。
- 清空所有数据：把网站重置成全新状态（成员、活动、报名、付款、设置全部删除，只保留群主密码）。需要两次确认、输入「清空所有数据」和群主密码；之后用当前群主密码在 /admin 重新做初次设置，做设置的人成为新的 Owner。用于交接给新的群主。

**界面要求**

- 纯中文。
- 两种外观风格，各 4 个低饱和度强调色，都有浅色和深色：
  - **简约**（默认，珊瑚橙 / 海蓝 / 森林绿 / 葡萄紫）：暖米白底、细边框、等宽小标签，克制耐看。
  - **极光**（紫青 / 日落 / 海洋 / 薄荷）：柔和彩色光晕上的磨砂玻璃卡片，标题和金额带渐变。
  - Owner 在设置里选全站默认（默认 简约·珊瑚橙）；每个人可以点右上角 ◐ 换成自己喜欢的风格、强调色和模式（自动 / 浅色 / 深色），只保存在自己的手机上。
  - 活动用日历块（年 / 月日 / 星期）显示日期，状态用带圆点的标签；「待付款」固定琥珀色、「报名中」固定绿色，不随强调色变化。
  - 旧版本保存的 7 种配色自动换成最接近的新外观。
- 网站图标：金门大桥的两座塔和主缆（吊索画成羽毛球网），背后是 Fremont 的 Mission Peak 和山顶的观景杆，天上飞过一只羽毛球，可以「添加到主屏幕」像 App 一样打开（打开的是当时所在的页面，成员加的就是自己的专属页）。
- 微信分享卡片：活动链接发到微信时，预览显示活动名称、日期、时间、场馆、报名人数和截止时间（不含任何名字）；首页链接显示网站标题。
- 分享名片：首页有「生成分享名片」（整个网站）；活动卡片（公开活动页和成员自己的页面）上有「分享名片」，只有报名中的活动才显示。在手机上生成一张图片：网站图标和标题、活动的日期、时间和场馆、二维码和链接，不含任何名字；长按图片即可保存或转发，发到微信群（弹窗只有图片、提示和关闭按钮）。
- 加入日历：公开活动页和成员报名后的卡片上有「加入日历」（iPhone / Outlook 的 .ics 文件、Google 日历），包含时间、场馆、地址，提前 2 小时提醒；活动结束后不再显示。
- 移动端优先，按钮足够大，适合在手机上单手操作。
- 收款看板上「已收齐」要有明显的视觉提示。
- 二维码在页面上生成（可用前端 JS 库），Owner 可长按保存。

## 11. 数据模型建议

以下为数据库中各表的业务字段，实际表结构以技术设计文档为准。每天同步到 Google 表格的是 8 个标签页：成员、活动、报名、结算、应付款、付款明细、待确认收款、场馆（另有「同步记录」）；设置和通知日志不同步，专属令牌等密钥从不导出。

| 工作表 | 主要字段 |
| --- | --- |
| 成员 Members | 成员编号（注册时分配，终身不变）、用户名、微信名、给群主的留言、状态（待审核/正常/停用）、删除时间、专属令牌、申请时间、通过时间、身份（成员/组织者/管理员/群主；功能开关关着时没有组织者和管理员） |
| 活动 Events | 活动编号、活动代号（如 1006）、日期、开始时间、结束时间、地点、截止时间、状态（报名中/已截止/已 Finalize/已收齐/已取消）、Finalize 时间、是否停止催款、创建时间、负责人、收款人（群主写「群主」，组织者写名字；没记录的旧活动算群主） |
| 报名 Registrations | 报名编号、活动编号、成员编号、朋友序号（0 为本人）、朋友名字、是否到场、报名时间、最后修改时间、是否 Owner 添加 |
| 结算 Settlements | 活动编号、场地总费用、用球个数、球单价、报名人数、到场人数、每人场地费、每人球费、Finalize 时间 |
| 应付款 Payments | 活动编号、成员编号、应付金额、付款编号（备注用）、状态（未付/部分付款/已付）、实收净额（付款减退款）、已退款金额、付清时间；每一笔付款和退款单独记录（金额、方式 Venmo/手动/退款，退款为负数、Venmo 交易编号、付款人、时间）；导出和表格里每笔应付款多一列「钱在谁的账户」（这场的收款人） |
| 待确认 Unmatched | Venmo 交易编号、邮件 ID、付款人、金额、备注、收到时间、原因、处理状态（未处理/已关联/已忽略/已删除）、钱在谁的账户；与羽毛球无关的收款不保存 |
| 场馆 Locations | 场馆名称、地址、最近使用时间、使用次数 |
| 设置 Settings | 带朋友上限 N、Venmo 用户名、Zelle 账号、Telegram 令牌、聊天编号、Owner 管理令牌、提醒开关和时间、每日催款发送时间、上次提前截止设置、上次球单价、上次活动时间 |
| 通知日志 NotificationLog | 活动编号、通知类型、发送时间（用于避免重复发送） |

朋友在报名表中以「成员编号 + 朋友序号」表示，费用汇总到该成员在应付款表中的一行。

## 12. 明确不做的功能与未来扩展

**本期明确不做**

- 登录 Venmo 查询记录或自动发起收款请求
- 下载 Venmo 对账单 CSV 的对账方式
- 微信群机器人自动发消息
- Zelle 自动对账
- 人数上限、候补名单
- 计算或建议场地数量
- 自动按周生成活动
- 成员之间互相代付（用带朋友代替）
- 跨活动欠款累计显示
- 多退少补、余额抵扣等自动处理
- 活动取消的费用处理（取消即无费用）

**未来可能扩展**

- 组织者和管理员都已经实现（见第 3 节；每场活动的钱进发起人自己的 Venmo，每人设自己的 Gmail 转发）。权限按能力登记（`owner`、`data`、`group` 等），以后再加身份时给它分配能力即可，见[管理员设计](design/admin-role.zh.md)第 4 节。

**交付物（给 Claude Code）**

- 完整的 Cloudflare 项目代码（网页、接口、定时任务、邮件处理），放在 GitHub 仓库 likefudan/jaysbadminton，推送后自动部署
- 数据库建表脚本，以及用于每日同步到 Google 表格的 Apps Script
- 部署和设置说明：Cloudflare 部署与域名、邮件接收和 Gmail 转发过滤器、打开 Venmo 邮件通知、创建 Telegram 机器人、Google 表格同步脚本的安装（包括「此应用未经验证」提示的处理）
